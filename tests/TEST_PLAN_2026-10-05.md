## Gap-closing suites (added v2)

### G1 — Endgame reachability — `node tests/endgame-drive.mjs`
Every other live test stops after N turns. This drives a session to **each
terminal state** and asserts the ending + report:
- **WIN** — all `goal.win_conditions` met → `goal`/`success`
- **LOSS** — narrative collapse → `loss` (only after the `consecutive` streak)
- **TIMEOUT** — timer expiry → `timeout`
- One **real-model** run plays badly on purpose (roll 1) to reach a real loss.
Expect: 15/15.

### G2 — Two-sided audit trail — `node tests/playability-audit.mjs`
Drives a real session and asserts **both sides** of the DM↔player exchange are
logged every turn (exact system+user prompt, raw pre-parse reply, shown
narrative), and the report embeds the full transcript. Writes JSON + HTML to
`tests/out/`. Expect: 12/12.

### G3 — Live-bundle proof — `node tests/live-browser-budget.mjs [--browser]`
Closes the gap that the fix was only unit-tested. Static mode fetches the
**deployed** Pages bundle and asserts the raised budgets + audit capture are
present. `--browser` boots the live site headless, points it at a local mock,
and captures the **actual outbound request**: opening carries `max_tokens=4096`
(scene), a real turn carries `max_tokens=8192` (the fix). Expect: 14/14.

## Story win (added v4, Dan's design 2026-10-05)
- **Win = narrative resolution, not a score gate.** The session succeeds when
  EITHER the final story beat is reached OR every attack-chain stage is
  contained. `endCondition.success_kind === 'story'`.
- **Metrics are advisory.** `goal.win_conditions` no longer gates the win; they
  only set a win-quality tier (`decisive` / `solid` / `costly`) + summary, so a
  story win with ragged numbers still WINS (it just reads as costlier).
- **UI:** a new **Objective** panel shows the story goal + the beat arc (with
  the current step highlighted) and states plainly that the win is narrative.
- **Report:** Result reads "Success — the story resolves"; a "How it reads" line
  carries the win-quality summary.
- **Docs:** each scenario's `goal.win_conditions_note` marks the thresholds as
  advisory-only.

### Tests for the story win
- `dm-session.test.js` — final-beat win, chain-containment win, low-metrics win,
  win-quality tier, no-goal scenario now WINS on full containment.
- `endgame-drive.mjs` — drives a story win (chain containment) AND a low-metric
  win AND the narrative loss AND timeout; real-model run reaches a loss.

## Pass criteria
- T1 153/0 (+ report additions); E 43/43; G1 16/16; G2 16/16; G3 14/14; L3 17/17; L4 5/5; R1 6/6.
- No truncated / JSON-leaking / fallback / no-op-dead-end narratives anywhere.
- A session can reach a STORY WIN (final beat / full containment), a narrative
  loss (collapse), and a timeout; each ending + report builds.
- Low metrics do NOT block a story win (advisory only).
- Fate twists fire and are recorded for rolls 1/11/20.
- The report shows both sides of the conversation, player attribution, token + cost
  accounting, and the story outcome; the HTML export downloads.

## Remaining gaps (reviewed v3, accepted for now)
- **Cross-browser**: automated browser tests run on Chromium only (Chromium is the
  only engine installed here). Manual spot-check on Safari/Firefox before a release.
- **Two-tab live test**: the active-tab lock is implemented + unit-guarded but there
  is no automated *two real tabs* test (puppeteer multi-page would be the next step).
- **Cost table maintenance**: prices are a static best-effort list; they drift. The
  figure is labelled *indicative* for that reason.
- **Direct-API live play**: the raised budgets are proven on the Ollama path (E/G)
  and the deployed bundle carries them (G3), but a full session against
  api.deepseek.com is Dan's manual acceptance run, not automated.
